6장. 키-값 저장소 설계

Key-Value Store. 5장 안정 해시가 데이터 파티션에 쓰인다.
보충 표시는 공부 노트에 없던 내용을 보강한 부분이다.

1. 키-값 저장소란

  • 비관계형(NoSQL) 데이터베이스. 고유한 키에 값이 연결된다
  • 키는 유일해야 하고, 값은 키로만 접근. 키는 짧을수록 성능에 좋다
  • 대표 제품 : DynamoDB, Memcached, Redis, Cassandra
  • 보충 설계 목표 : 높은 가용성 / 높은 규모 확장성 / 일관성 수준 조정 가능 / 낮은 응답 지연

2. 단일 서버 키-값 저장소

  • 서버 한 대는 쉽다. 가장 나이브하게 키-값 쌍 전부를 메모리의 해시 테이블에 저장
  • 전부 메모리에 두는 게 불가능하면 :
    • 데이터 압축
    • 자주 쓰는 데이터만 메모리, 나머지는 디스크
  • 그래도 한 대는 한계 → 분산 키-값 저장소

3. 분산 키-값 저장소 : CAP 정리

요소의미
C 일관성
(Consistency)		어떤 노드에 접속하든 언제나 같은 데이터를 본다
A 가용성
(Availability)		일부 노드에 장애가 나도 항상 응답을 받는다
P 파티션 감내
(Partition tolerance)		파티션 = 두 노드 사이의 통신 장애. 파티션이 생겨도 시스템은 계속 동작
세 가지를 모두 만족하는 건 불가능.
네트워크 장애는 피할 수 없으므로 분산 저장소는 P 를 품고 간다.
그래서 선택은 CP (가용성 희생) 아니면 AP (일관성 희생).
CA 는 현실의 분산 시스템에선 불가능.

이상 vs 실세계

  • 이상 : n1, n2, n3 사이 파티션이 안 생김 → 쓴 데이터가 즉시 복제 → C 와 A 모두 만족
  • 실세계 : n3 가 단절되면 n1, n2 의 최신 데이터가 n3 로 가지 못한다 → n3 는 오래된 사본
선택동작대가
CP
(일관성 선택)		 불일치를 막기 위해 n1, n2 의 쓰기를 중단 가용성이 깨진다. 예) 은행 : 잔액은 최신이어야 하므로 오류를 반환
AP
(가용성 선택)		 낡은 데이터 반환 위험이 있어도 읽기 허용, n1, n2 는 계속 쓰기 허용. 파티션이 해결되면 새 데이터를 n3 로 전송 일관성이 깨진다

4. 시스템 컴포넌트

4-1. 데이터 파티션

  • 전체 데이터를 한 서버에 못 두니 작게 나눠 여러 서버에 저장
  • 고려 : 데이터를 고르게 분산 / 노드 추가·삭제 시 이동 최소화 → 안정 해시(5장)
  • 장점 : 규모 확장 자동화, 다양성 (가상 노드를 서버 용량에 비례해 조절)

4-2. 데이터 다중화

  • 높은 가용성과 안정성을 위해 데이터를 N 개 서버에 비동기적으로 다중화
  • 키를 링에 배치한 후 시계 방향으로 N 개 서버에 사본 저장
  • 보충 가상 노드 때문에 같은 물리 서버가 중복 선택되지 않게 서로 다른 물리 서버 N 개를 고른다
  • 보충 사본은 다른 데이터 센터에 나눠 보관 (정전·재해 대비)

4-3. 데이터 일관성 : 정족수 (quorum)

  • N = 사본 수, W = 쓰기 성공으로 인정받는 데 필요한 응답 수, R = 읽기 성공에 필요한 응답 수
  • 보충 중재자(coordinator) 가 클라이언트와 노드 사이 프록시. W 개의 ack 가 오면 쓰기 성공
W + R > N → 보통 강한 일관성 보장 (겹치는 노드가 하나는 있어 최신을 읽음)
W + R <= N → 보장되지 않음
설정특성
R = 1, W = N빠른 읽기에 최적화 (쓰기는 느림)
W = 1, R = N빠른 쓰기에 최적화 (읽기는 느림)
W + R > N (예: N=3, W=R=2)강한 일관성
W + R <= N빠르지만 낡은 데이터를 볼 수 있음

4-4. 일관성 모델

모델설명
강한 일관성모든 읽기가 최신 결과를 반환. 낡은 데이터를 절대 못 봄 (모든 사본에 반영될 때까지 읽기/쓰기 금지 → 고가용성에는 부적절)
약한 일관성읽기가 최신 값을 반환하지 못할 수 있다
최종 일관성약한 일관성의 한 형태. 갱신 결과가 결국에는 모든 사본에 반영된다

보충 Dynamo, Cassandra 는 최종 일관성을 채택. 동시 쓰기로 불일치가 생기면 클라이언트가 해소한다.

4-5. 비일관성 해소 : 데이터 버저닝

  • 다중화하면 사본 간 불일치가 생긴다 (서버 1·2 가 동시에 같은 키에 다른 값을 쓰면 충돌)
  • 해결 : 변경마다 새 버전을 만들어 불변 데이터로 취급 → 벡터 시계(vector clock) 보충
  • 벡터 시계 = 데이터에 붙은 [서버, 버전] 쌍. 쓸 때 해당 서버 버전을 +1 (없으면 [Si, 1] 생성)
  • 모든 서버 카운터가 이전 이상이면 → 이전 버전의 후손 (충돌 없음)
  • 어떤 서버 카운터는 크고 어떤 건 작으면 → 형제(sibling) = 충돌 → 클라이언트가 해소
  • 단점 : 충돌 감지·해소 로직이 클라이언트에 들어가 복잡 / 쌍의 수가 빠르게 늘어남 (임계치 넘으면 오래된 쌍 제거)

4-6. 장애 처리

장애 감지 : 가십 프로토콜

  • 한 서버가 "죽었다" 고 해도 부족, 두 대 이상이 확인해야 장애로 판단
  • 모든 노드 간 멀티캐스팅은 서버가 많으면 비효율 → 분산형 장애 감지인 가십 프로토콜
  1. 각 노드는 멤버십 목록(멤버 ID, 박동 카운터)을 유지
  2. 각 노드는 주기적으로 자기 박동 카운터를 증가
  3. 무작위로 고른 노드들에게 박동 카운터 목록을 전송
  4. 받은 노드는 멤버십 목록을 최신으로 갱신
  5. 어떤 멤버의 카운터가 지정 시간 동안 갱신되지 않으면 장애(offline)로 간주

일시적 장애 처리

  • 엄격한 정족수에서는 읽기·쓰기가 금지될 수 있다
  • 느슨한 정족수(sloppy quorum) : 장애 서버를 건너뛰고 해시 링에서 건강한 서버 W 개/R 개를 골라 처리 (가용성 유지)
  • 장애 서버가 복구되면 일괄 반영하여 일관성 유지. 임시 처리 서버에 단서(hint) 를 남김 → 임시 위탁(hinted handoff)

영구 장애 처리

  • 반-엔트로피(anti-entropy) 프로토콜 : 사본들을 비교해 최신 버전으로 갱신
  • 일관성 손상 탐지와 전송량 감소를 위해 머클 트리 사용
  • 보충 머클 트리 : 키 범위(버킷)의 해시를 리프로 하여 부모 해시를 올려 만든 해시 트리. 두 서버의 루트가 같으면 동일, 다르면 자식을 내려가며 다른 버킷만 찾아 그 부분만 동기화

데이터 센터 장애

  • 정전·네트워크 장애·재해 대비 → 여러 데이터 센터에 다중화

4-7. 시스템 아키텍처

  • 클라이언트는 두 가지 단순 API 로 통신 : get(key), put(key, value)
  • 중재자(coordinator) : 클라이언트에게 키-값 저장소에 대한 프록시 역할을 하는 노드
  • 노드는 안정 해시의 해시 링 위에 분포
  • 노드를 자동으로 추가/삭제할 수 있도록 시스템은 완전히 분산
  • 모든 노드가 같은 책임을 지므로 SPOF 가 없다
  • 보충 각 노드의 기능 : 클라이언트 API, 장애 감지, 충돌 해소, 장애 복구, 다중화, 저장소 엔진, 일관성

4-8. 쓰기 경로 보충 (Cassandra 기준)

  1. 쓰기 요청이 커밋 로그 파일에 기록
  2. 데이터가 메모리 캐시(memtable) 에 기록
  3. 메모리 캐시가 가득 차면 디스크의 SSTable 에 기록 (정렬된 <key, value> 리스트)

4-9. 읽기 경로 보충

  1. 데이터가 메모리에 있나 확인 → 있으면 반환
  2. 없으면 블룸 필터로 어떤 SSTable 에 키가 있을지 확인
  3. 해당 SSTable 에서 가져와 반환

블룸 필터 : "있을 수도 있다 / 확실히 없다" 를 작은 메모리로 판별하는 확률적 자료구조 (거짓 양성은 있고 거짓 음성은 없음).

5. 목표 ↔ 기술 정리 보충

목표 / 문제기술
대규모 데이터 저장안정 해시로 서버들에 부하 분산
읽기 높은 가용성여러 데이터 센터에 다중화
쓰기 높은 가용성버저닝 + 클라이언트 충돌 해소
조절 가능한 일관성정족수 합의 (N, W, R)
일시적 장애느슨한 정족수 + 임시 위탁
영구적 장애머클 트리 (anti-entropy)
장애 감지가십 프로토콜
데이터 센터 장애여러 데이터 센터에 다중화

복습 퀴즈 (눌러서 답 확인)

1. 단일 서버에서 메모리가 부족하면?

데이터 압축, 자주 쓰는 데이터만 메모리에 두고 나머지는 디스크에 저장.

2. 분산 시스템은 왜 CP 아니면 AP 인가?

네트워크 파티션(P)은 피할 수 없어서 P 는 항상 가져가고, 일관성(C)과 가용성(A) 중 하나를 희생한다.

3. n3 가 단절됐을 때 CP 와 AP 의 동작은?

CP : n1, n2 의 쓰기를 중단 (가용성 깨짐). AP : 낡은 데이터 위험이 있어도 읽기/쓰기 허용하고, 복구 후 n3 에 새 데이터 전송 (일관성 깨짐).

4. N=3 에서 강한 일관성을 얻으려면? R=1, W=N 은?

W + R > N, 예) W=2, R=2. R=1, W=N 은 읽기가 빠르게 최적화된 설정.

5. 최종 일관성이란? 쓰는 시스템은?

시간이 지나면 결국 모든 사본이 같아지는 모델. Dynamo, Cassandra.

6. 벡터 시계로 충돌을 어떻게 감지하나? 단점은?

[서버, 버전] 쌍을 비교해 한쪽이 다른 쪽의 모든 카운터 이상이면 후손(충돌 없음), 아니면 형제(충돌). 단점 : 클라이언트 로직이 복잡하고 쌍이 늘어난다.

7. 가십 프로토콜의 동작은?

노드가 자기 박동 카운터를 올리고, 무작위 노드들에 멤버십 목록을 전송. 일정 시간 카운터가 안 오르는 노드는 장애로 간주.

8. 일시적 장애와 영구 장애의 처리 차이는?

일시적 : 느슨한 정족수 + 임시 위탁(hinted handoff). 영구 : 반-엔트로피 + 머클 트리로 사본 동기화.

9. SPOF 가 없는 이유는?

모든 노드가 같은 책임을 지고, 데이터는 여러 노드에 다중화되며, 노드가 완전히 분산돼 있기 때문.
