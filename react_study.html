1. JSX 에 HTML 적용하기 (예제 1)

JSX : JavaScript 안에 HTML 처럼 화면을 적는 문법. 컴포넌트(함수)가 return 으로 JSX 를 돌려주면 React 가 그걸 화면에 그린다. 

// src/App.jsx
function App() {
  return (
    <div>
      <h1>Hello React 200제</h1>
    </div>
  )
}

export default App      // 다른 파일(main.jsx)에서 가져다 쓸 수 있게 내보내기

JSX 가 HTML 과 다른 점 보충

규칙예
return 하는 JSX 는 최상위 태그가 하나여야 한다<div>...</div> 로 감싸거나 빈 껍데기 <> ... </> (Fragment)
여러 줄이면 소괄호 ( ) 로 감싼다return ( <div>...</div> )
모든 태그는 닫아야 한다<br />, <img />, <input />
class 대신 className<p className="title"> (class 는 JS 예약어)
JS 값은 { } 안에<p>{1 + 2}</p>, <p>{name}</p> (템플릿 리터럴의 ${ } 와 비슷)
주석은 {/* */}{/* 화면에 안 보이는 메모 */}

2. JSX 에 CSS 적용하기 (예제 2)

CSS 파일을 만들고 컴포넌트 파일에서 import 하면 적용된다.

/* src/App.css */
div {
  background-color: rgb(162, 127, 243);
  color: rgb(255, 255, 255);
  padding: 40px;
  font-family: 고딕;
  text-align: center;
}
h1 {
  color: white;
  background-color: #2EFE2E;
  padding: 10px;
  font-family: 궁서;
}
// src/App.jsx
import './App.css'          // CSS 파일 가져오기 (이름 없이 경로만)

function App() {
  return (
    <div>
      <h1>Hello React 200제</h1>
      <p>CSS 적용하기</p>
    </div>
  )
}

스타일을 주는 방법 보충

방법예특징
CSS 파일 importimport './App.css'CSS 노트에서 배운 그대로. 가장 기본
className<p className="title"> + .title { }HTML 의 class 와 같은 역할
인라인 style<p style={{ color: 'red', fontSize: 20 }}>값이 객체. 속성 이름은 카멜 표기(font-size → fontSize)

보충 App.css 를 App 에서 import 해도 App 에만 적용되는 게 아니라 페이지 전체에 적용된다. 위 예제의 div { } 는 다른 컴포넌트의 div 에도 모두 적용된다. 그래서 보통 태그 선택자보다 className 을 쓴다. style={{ }} 의 바깥 { } 는 "JS 값을 넣는다", 안쪽 { } 는 "객체" 라는 뜻이다.

3. Component 사용하기 (예제 3)

컴포넌트 : 화면의 한 조각을 만드는 재사용 가능한 부품. 파일로 따로 만들고 export 한 뒤, 쓰는 쪽에서 import 해서 태그처럼 사용한다. 

// src/R003_ImportConponent.jsx   (책의 R003 파일, 확장자는 .jsx)
import React, { Component } from "react";

class R003_ImportConponet extends Component {   // 클래스형 컴포넌트
    render() {
        return (                                  // ( ) 소괄호!
            <h2>[THIS IS IMPORTED COMPONENT]</h2>
        )
    }
}

export default R003_ImportConponet;              // 기본(default)으로 내보내기
// src/App.jsx
import './App.css'
import ImportConponet from './R003_ImportConponent'   // ① 가져오기 (파일 경로)

function App() {
  return (
    <div>
      <h1>Hello React 200제</h1>
      <p>CSS 적용하기</p>
      <ImportConponet></ImportConponet>              {/* ② 태그처럼 사용 */}
    </div>
  )
}
포인트설명
export default 이름이 파일의 대표로 내보낸다. 받는 쪽은 아무 이름으로나 받을 수 있다
import 이름 from './파일'경로는 파일 이름과 정확히 같아야 한다 (.jsx 는 생략 가능)
태그 이름import 할 때 붙인 이름과 같아야 한다 (철자 주의)
대문자로 시작컴포넌트 이름은 반드시 대문자. 소문자면 일반 HTML 태그로 착각한다
<X></X> = <X />사이에 내용이 없으면 스스로 닫는 태그로 줄여 쓸 수 있다 (결과 같음)

실습하며 겪은 실수

실수원인 / 해결
return { <h2>...</h2> } → 에러{ } 는 객체로 읽힌다. JSX 는 소괄호 ( ) 로 감싼다
컴포넌트 파일만 만들고 화면에 안 나옴쓰는 쪽(App.jsx)에서 import 하고 태그로 써야 나온다
<ImpoortConponent> (o 두 개)import 한 이름과 달라서 is not defined 에러. 철자 확인

보충 import 경로의 대소문자도 파일 이름과 맞추자. 예) 파일은 R003_ImportConponent.jsx 인데 './R003_importConponent' 로 쓰면 Windows 에서는 동작하지만, 대소문자를 구분하는 리눅스 서버(배포 환경)에서는 파일을 못 찾는다.

클래스형 vs 함수형 컴포넌트 보충

책은 클래스형으로 시작하지만, 요즘은 거의 함수형을 쓴다. 위 예제를 함수형으로 쓰면 :

// 함수형 : 함수가 JSX 를 return 하면 끝 (render 메서드, Component 상속 필요 없음)
function R003_ImportConponet() {
  return <h2>[THIS IS IMPORTED COMPONENT]</h2>
}

export default R003_ImportConponet
구분클래스형함수형
모양class X extends Component { render() { return (...) } }function X() { return (...) }
상태 관리this.state, this.setStateuseState 같은 Hook
지금옛 코드·책에서 자주 보임. React 19 에서도 동작현재 표준 (Vite 기본 App.jsx 도 함수형)

4. 생명주기 함수 (예제 4 ~ 6)

클래스형 컴포넌트에는 React 가 정해진 시점에 자동으로 호출하는 메서드들이 있다. 이를 생명주기(LifeCycle) 함수라고 한다. 내가 호출하는 게 아니라 React 가 이름으로 찾아서 호출한다.

순서생명주기 함수 (마운트 : 처음 화면에 올라갈 때)하는 일
1constructor(props)생성자. state 선언, props 초기화
2static getDerivedStateFromProps(props, state)props 를 보고 state 조정
3render()화면(JSX) 만들기
4componentDidMount() 보충화면에 붙은 직후 (다음 예제)

코드에 적은 위치는 상관없다. R006 처럼 getDerivedStateFromProps 를 constructor 보다 위에 적어도 실행 순서는 React 가 정한 대로다.

4-1. render() (예제 4)

// src/R004_LifeCycleEx.jsx
import React, { Component } from 'react';

class R004_LifecycleEx extends Component {
    render() {
        console.log('3. render Call');
        return (
            <h2>[THIS IS RENDER FUNCTION]</h2>
        )
    }
}

export default R004_LifecycleEx;
  • 화면에 그릴 JSX 를 return 하는 함수. 클래스형 컴포넌트에 반드시 있어야 한다
  • 보충 처음 마운트될 때뿐 아니라 props 나 state 가 바뀔 때마다 다시 호출된다
  • 보충 render 안에서는 화면을 계산만 한다. 여기서 state 를 바꾸면(setState) 다시 render → 무한 반복이 된다

4-2. constructor(props) (예제 5)

// src/R005_LifeCycleEx.jsx
class R005_LifecycleEx extends Component {
    constructor(props) {
        super(props);                    // 가장 위에서 먼저 호출!
        this.state = {};                 // 컴포넌트 안에서 쓸 변수(state) 선언
        console.log('1. constructor Call');
    }
    render() {
        console.log('3. render Call');
        return (
            <h2>[THIS IS CONSTRUCTOR FUNCTION]</h2>
        )
    }
}
  • 생명주기 함수 중 가장 먼저 실행되고, 처음 한 번만 호출된다
  • 컴포넌트 내부에서 사용되는 변수(state)를 선언하고, 부모 객체에서 전달받은 변수(props)를 초기화할 때 사용한다
  • super(props) 는 가장 위에서 호출해야 한다

보충 super(props) 는 부모 클래스(Component)의 생성자를 부르는 것. 이게 끝나야 this 를 쓸 수 있어서, super 전에 this.state 를 쓰면 ReferenceError 가 난다 (C++ 의 부모 생성자 호출과 같은 개념). constructor 안에서는 this.setState() 대신 this.state = { ... } 로 직접 대입한다.

4-3. getDerivedStateFromProps (예제 6)

// src/R006_LifeCycleEx.jsx
class R006_LifecycleEx extends Component {
    static getDerivedStateFromProps(props, state) {
        console.log('2. getDerivedStateFromProps Call :' + props.prop_value);
        return {};                       // state 에 합칠 객체 (바꿀 게 없으면 null)
    }
    constructor(props) {
        super(props);
        this.state = {};
        console.log('1. constructor Call');
    }
    render() {
        console.log('3. render Call');
        return (
            <h2>[THIS IS CONSTRUCTOR FUNCTION]</h2>
        )
    }
}
// src/App.jsx : 부모가 prop_value 를 넘겨준다
import LifecycleEx from './R006_LifeCycleEx'
...
<LifecycleEx prop_value="FromApp.jsx" />
// 콘솔 (F12 → Console)
1. constructor Call
2. getDerivedStateFromProps Call :FromApp.jsx
3. render Call
  • getDerivedStateFromProps 는 React 가 예약해 둔 이름이다. 이걸로 props 를 받아서 state 를 조정한다
  • 호출 순서 : constructor → getDerivedStateFromProps → render
  • 컴포넌트가 새로운 props 를 받게 됐을 때 state 를 변경해 준다 (마운트 때와 다시 그릴 때마다 render 직전에 호출)
왜 이런가 보충설명
constructor 다음state 를 고치는 함수라서 constructor 에서 this.state 가 먼저 만들어져 있어야 한다
render 앞조정한 state 로 화면을 그려야 하니까
static클래스에 붙은 함수라 this 를 못 쓴다. 받은 props, state 만 보고 바꿀 내용을 객체로 return → React 가 state 에 합친다

보충 생명주기 함수는 이름을 틀리면 에러 없이 그냥 호출되지 않는다. 콘솔에 로그가 안 찍히면 철자부터 확인. 또 class X extends Componet 처럼 Component 철자가 틀리면 ReferenceError: Componet is not defined 로 화면 전체가 하얗게 된다 → F12 Console 에서 확인. getDerivedStateFromProps 는 실무에서는 거의 쓰지 않는다. 지금은 순서 이해용.

4-4. props : 부모가 넘겨주는 값

  • props = properties(속성) 의 준말. HTML 태그에 속성을 붙이듯 컴포넌트 태그에 붙인 속성들을 모은 객체
  • <LifecycleEx prop_value="FromApp.jsx" /> → 자식은 props = { prop_value: "FromApp.jsx" } 를 받는다
  • prop_value 는 예약어가 아니라 책에서 정한 이름. 양쪽 이름만 맞추면 아무 이름이나 된다
  • 클래스형 컴포넌트의 메서드 안에서는 this.props.prop_value 로 꺼낸다 보충
  • 문자열은 "...", 숫자나 JS 값은 { } 로 넘긴다 : <X age={30} /> 보충
구분예
React 가 정한 이름props(매개변수 이름은 관례), render, constructor, getDerivedStateFromProps, componentDidMount, state, setState
내가 정하는 이름prop_value 같은 속성 이름, 컴포넌트 이름
피해야 할 속성 이름 보충key, ref (React 가 따로 씀, props 로 안 넘어감), children (태그 사이 내용)

4-5. 콘솔에 두 번씩 찍히는 이유 : StrictMode 보충

  • main.jsx 의 <StrictMode> 는 개발할 때만 동작하는 검사 모드. constructor, getDerivedStateFromProps, render 를 일부러 두 번씩 호출한다
  • 같은 입력이면 같은 결과가 나와야 하는 함수에 숨은 버그(부수 효과)를 찾기 위해서. 배포용(npm run build)에서는 한 번만 실행된다
  • 책처럼 한 번씩 보고 싶으면 잠시 main.jsx 를 createRoot(...).render(<App />) 로 바꾼다 (공부 후 다시 켜기)

복습 퀴즈 (눌러서 답 확인)

1. 개발 서버를 켜는 명령과 접속 주소는?

react_study 폴더에서 npm run dev, 주소는 http://localhost:5173/. 터미널을 닫으면 서버도 꺼진다.

2. 책의 App.js 와 index.js 는 내 프로젝트에서 어떤 파일인가?

App.js → src/App.jsx, index.js → src/main.jsx. 새 파일은 확장자를 .jsx 로 만든다.

3. JSX 에서 class 대신 쓰는 속성은? JS 값을 넣는 방법은?

className. JS 값은 { } 안에 넣는다.

4. return 할 때 ( ) 대신 { } 를 쓰면?

JavaScript 가 객체를 돌려주는 것으로 읽어서 문법 에러가 난다. JSX 는 소괄호로 감싼다.

5. 컴포넌트를 다른 파일에서 쓰려면?

컴포넌트 파일에서 export default 로 내보내고, 쓰는 파일에서 import 이름 from './파일' 한 뒤 <이름 /> 태그로 쓴다. 이름은 대문자로 시작.

6. <X></X> 와 <X /> 의 차이는?

내용이 없을 때는 결과가 같다. 사이에 내용(children)을 넣을 때만 여는/닫는 태그를 쓴다.

7. 마운트 때 생명주기 함수의 호출 순서는?

constructor → getDerivedStateFromProps → render (→ componentDidMount). 코드에 적은 순서와 상관없다.

8. constructor 에서 하는 일과 super(props) 를 맨 위에 쓰는 이유는?

state 선언과 props 초기화. 처음 한 번만 호출된다. super 로 부모(Component) 생성자를 먼저 불러야 this 를 쓸 수 있다.

9. getDerivedStateFromProps 는 왜 static 이고 무엇을 return 하나?

this 를 쓰지 못하게 해서 받은 props·state 만으로 계산하게 하려고. state 에 합칠 객체를 return 하고, 바꿀 게 없으면 null.

10. props 는 무엇의 준말이고 prop_value 는 예약어인가?

properties(속성). 부모가 컴포넌트 태그에 붙인 속성들의 객체다. prop_value 는 책이 정한 이름일 뿐 예약어가 아니다.

11. 콘솔에 로그가 두 번씩 찍히는 이유는?

main.jsx 의 StrictMode 가 개발 중에 버그를 찾으려고 일부러 두 번 호출하기 때문. 배포용에서는 한 번.
