5장. 안정 해시 설계

Consistent Hashing. 1장 샤딩의 "재샤딩" 문제를 푸는 기술이다.
보충 표시는 공부 노트에 없던 내용을 보강한 부분이다.

1. 해시 키 재배치 문제

  • 수평 확장에는 요청/데이터를 서버에 균등하게 분배해야 한다
  • 보충 기본 방식 (나머지 연산 해시) :
serverIndex = hash(key) % N    // N = 서버 대수
  • 서버 수가 고정이면 잘 동작하지만, 서버가 추가/삭제되면 N 이 바뀌어 거의 모든 키가 재배치된다
  • 보충 예) 서버 4대 중 1대 장애 → % 3 으로 바뀜 → 대부분 엉뚱한 서버로 접속 → 캐시 미스 폭증 → 대규모 장애

그래서 안정 해시를 사용한다.

2. 안정 해시란

해시 테이블 크기가 조정될 때 평균적으로 오직 k/n 개의 키만 재배치하는 해시 기술
(k = 키의 개수, n = 슬롯(서버)의 개수)

3. 해시 링 (hash ring)

  • 해시 공간 : 해시 함수의 출력 범위. SHA-1 이면 0 ~ 2160 - 1
  • 이 공간의 양쪽 끝을 구부려 접어 원형(링)으로 만든다
  • 서버와 키를 같은 균등 분포 해시 함수로 링 위에 배치 (나머지 연산 없음)
  • 키가 저장될 서버 : 키 위치에서 시계 방향으로 탐색하다 처음 만나는 서버
링 위 배치 (시계 방향)
s0 → k0 → s1 → s2 → s3 → (다시 s0)

k0 는 시계 방향 첫 서버인 s1 에 저장
상황일어나는 일
서버 추가새 서버와 바로 앞(반시계) 서버 사이 구간의 키만 새 서버로 이동 → 일부 키만 재배치
서버 제거제거된 서버의 키만 시계 방향 다음 서버로 이동 → 일부 키만 재배치

4. 기본 구현의 두 가지 문제

문제설명
파티션 크기 불균형서버 간 구간(파티션) 크기를 균등하게 유지하기 어렵다 (어떤 서버는 구간이 아주 넓고 어떤 서버는 좁음)
키 분포 불균형링 위의 키가 균등하게 분포하지 않을 수 있다 (일부 서버에 몰림)

5. 가상 노드 (virtual node)

  • 실제 서버 하나를 링 위에 여러 개의 가상 노드로 표현한다
  • 서버마다 여러 파티션을 담당 (예: s0 → s0_0, s0_1, s0_2 …)
  • 키는 시계 방향으로 만나는 첫 가상 노드가 가리키는 실제 서버에 저장
  • 가상 노드 수를 늘릴수록 키 분포가 더 균등해진다 (표준 편차 감소)
  • 보충 연구 결과 가상 노드 100~200개면 표준 편차가 평균의 약 5~10%
  • 보충 트레이드오프 : 가상 노드 데이터를 저장할 공간이 더 필요 → 요구사항에 맞게 튜닝

6. 안정 해시의 이점

  1. 서버 추가/삭제 시 재배치되는 키의 수가 최소화
  2. 데이터가 균등하게 분포 → 수평적 규모 확장이 쉽다
  3. 핫스팟 키 문제를 줄인다

7. 실제 사용처 보충

  • Amazon DynamoDB 의 파티셔닝
  • Apache Cassandra 의 데이터 파티셔닝
  • Discord 채팅 애플리케이션
  • Akamai CDN
  • Google Maglev 네트워크 로드 밸런서

복습 퀴즈 (눌러서 답 확인)

1. hash(key) % N 방식에서 서버가 하나 줄면?

N 이 바뀌어 대부분의 키가 다른 서버로 재배치된다. 캐시라면 미스가 폭증한다.

2. 안정 해시에서 서버 추가/삭제 시 재배치되는 키의 수는?

평균 k/n 개 (키 개수 / 슬롯 개수).

3. 키가 저장될 서버는 어떻게 정하나?

키의 해시 위치에서 링을 시계 방향으로 탐색해 처음 만나는 서버.

4. 기본 해시 링의 두 가지 문제와 해결책은?

파티션 크기 불균형, 키 분포 불균형 → 가상 노드로 해결.

5. 가상 노드를 늘리면 장점과 단점은?

장점 : 키 분포가 더 균등해진다. 단점 : 가상 노드 데이터를 저장할 공간이 더 든다.

6. 1장 샤딩의 어떤 문제를 해결하나?

재샤딩 문제(데이터 재배치)와 핫스팟 키 문제.

더 공부할 거리 보충

  • 안정 해시 외 방식 : rendezvous(HRW) hashing, jump consistent hash
  • Cassandra 의 복제 (링에서 N 개 서버에 복제)
  • 분산 캐시 (Memcached 클라이언트 샤딩)
