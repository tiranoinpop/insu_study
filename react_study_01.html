React 스터디 1단락 : 시작하기와 컴포넌트 생명주기

교재 : 초보자를 위한 리액트 200제 예제 1~8 (책은 옛 create-react-app 기준, 실습은 Vite + React 19).
실습 코드 : github.com/tiranoinpop/react_study
보충 표시는 공부 노트에 없던 내용을 보강한 부분이다.

★ 핵심 : 컴포넌트 생명주기

클래스형 컴포넌트는 태어나고(마운트) → 바뀌고(업데이트) → 사라진다(언마운트). 각 시점에 React 가 정해진 이름의 메서드를 정해진 순서로 자동 호출한다. 이 단락에서 가장 중요한 내용이다.

단계순서대로 호출되는 함수하는 일
마운트
(처음 한 번)		① constructor
② getDerivedStateFromProps
③ render
④ componentDidMount		① state 초기화 ② props 로 state 조정 ③ 화면 그리기 ④ 화면에 붙은 직후 (데이터 가져오기, 타이머 시작)
업데이트
(props 변경, setState)		① getDerivedStateFromProps
② shouldComponentUpdate
③ render
④ getSnapshotBeforeUpdate
⑤ componentDidUpdate		② 다시 그릴지 결정 (false 면 멈춤) ③ 다시 그리기 ④ 반영 직전 기록 ⑤ 반영 직후 작업
언마운트
(사라질 때)		componentWillUnmount정리 작업 (타이머 해제 등)
· 생명주기 함수는 내가 호출하지 않는다. React 가 이름으로 찾아서 정해진 순서로 호출한다 (코드에 적은 위치와 무관)
· 이름을 틀리면 에러 없이 그냥 호출되지 않는다
· return 값의 의미도 React 가 정했다 : render → 화면에 그림, getDerivedStateFromProps → state 에 합침, shouldComponentUpdate → 다시 그릴지 여부
· 짝 : componentDidMount(시작) ↔ componentWillUnmount(정리), getSnapshotBeforeUpdate(기록) ↔ componentDidUpdate(사용)

보충 책의 componentWillMount, componentWillReceiveProps, componentWillUpdate 는 옛 함수다 (React 19 에서는 UNSAFE_ 를 붙여야 동작, 경고). 함수형 컴포넌트에는 이 메서드들이 없고, componentDidMount · componentDidUpdate · componentWillUnmount 를 useEffect 하나로 처리한다.

1. JSX 에 HTML 적용하기 (예제 1)

JSX : JavaScript 안에 HTML 처럼 화면을 적는 문법. 컴포넌트(함수)가 return 으로 JSX 를 돌려주면 React 가 그걸 화면에 그린다. 

// src/App.jsx
function App() {
  return (
    <div>
      <h1>Hello React 200제</h1>
    </div>
  )
}

export default App      // 다른 파일(main.jsx)에서 가져다 쓸 수 있게 내보내기

JSX 가 HTML 과 다른 점 보충

규칙예
return 하는 JSX 는 최상위 태그가 하나여야 한다<div>...</div> 로 감싸거나 빈 껍데기 <> ... </> (Fragment)
여러 줄이면 소괄호 ( ) 로 감싼다return ( <div>...</div> )
모든 태그는 닫아야 한다<br />, <img />, <input />
class 대신 className<p className="title"> (class 는 JS 예약어)
JS 값은 { } 안에<p>{1 + 2}</p>, <p>{name}</p> (템플릿 리터럴의 ${ } 와 비슷)
주석은 {/* */}{/* 화면에 안 보이는 메모 */}

2. JSX 에 CSS 적용하기 (예제 2)

CSS 파일을 만들고 컴포넌트 파일에서 import 하면 적용된다.

/* src/App.css */
div {
  background-color: rgb(162, 127, 243);
  color: rgb(255, 255, 255);
  padding: 40px;
  font-family: 고딕;
  text-align: center;
}
h1 {
  color: white;
  background-color: #2EFE2E;
  padding: 10px;
  font-family: 궁서;
}
// src/App.jsx
import './App.css'          // CSS 파일 가져오기 (이름 없이 경로만)

function App() {
  return (
    <div>
      <h1>Hello React 200제</h1>
      <p>CSS 적용하기</p>
    </div>
  )
}

스타일을 주는 방법 보충

방법예특징
CSS 파일 importimport './App.css'CSS 노트에서 배운 그대로. 가장 기본
className<p className="title"> + .title { }HTML 의 class 와 같은 역할
인라인 style<p style={{ color: 'red', fontSize: 20 }}>값이 객체. 속성 이름은 카멜 표기(font-size → fontSize)

보충 App.css 를 App 에서 import 해도 App 에만 적용되는 게 아니라 페이지 전체에 적용된다. 위 예제의 div { } 는 다른 컴포넌트의 div 에도 모두 적용된다. 그래서 보통 태그 선택자보다 className 을 쓴다. style={{ }} 의 바깥 { } 는 "JS 값을 넣는다", 안쪽 { } 는 "객체" 라는 뜻이다.

3. Component 사용하기 (예제 3)

컴포넌트 : 화면의 한 조각을 만드는 재사용 가능한 부품. 파일로 따로 만들고 export 한 뒤, 쓰는 쪽에서 import 해서 태그처럼 사용한다. 

// src/R003_ImportConponent.jsx   (책의 R003 파일, 확장자는 .jsx)
import React, { Component } from "react";

class R003_ImportConponet extends Component {   // 클래스형 컴포넌트
    render() {
        return (                                  // ( ) 소괄호!
            <h2>[THIS IS IMPORTED COMPONENT]</h2>
        )
    }
}

export default R003_ImportConponet;              // 기본(default)으로 내보내기
// src/App.jsx
import './App.css'
import ImportConponet from './R003_ImportConponent'   // ① 가져오기 (파일 경로)

function App() {
  return (
    <div>
      <h1>Hello React 200제</h1>
      <p>CSS 적용하기</p>
      <ImportConponet></ImportConponet>              {/* ② 태그처럼 사용 */}
    </div>
  )
}
포인트설명
export default 이름이 파일의 대표로 내보낸다. 받는 쪽은 아무 이름으로나 받을 수 있다
import 이름 from './파일'경로는 파일 이름과 정확히 같아야 한다 (.jsx 는 생략 가능)
태그 이름import 할 때 붙인 이름과 같아야 한다 (철자 주의)
대문자로 시작컴포넌트 이름은 반드시 대문자. 소문자면 일반 HTML 태그로 착각한다
<X></X> = <X />사이에 내용이 없으면 스스로 닫는 태그로 줄여 쓸 수 있다 (결과 같음)

실습하며 겪은 실수

실수원인 / 해결
return { <h2>...</h2> } → 에러{ } 는 객체로 읽힌다. JSX 는 소괄호 ( ) 로 감싼다
컴포넌트 파일만 만들고 화면에 안 나옴쓰는 쪽(App.jsx)에서 import 하고 태그로 써야 나온다
<ImpoortConponent> (o 두 개)import 한 이름과 달라서 is not defined 에러. 철자 확인

보충 import 경로의 대소문자도 파일 이름과 맞추자. 예) 파일은 R003_ImportConponent.jsx 인데 './R003_importConponent' 로 쓰면 Windows 에서는 동작하지만, 대소문자를 구분하는 리눅스 서버(배포 환경)에서는 파일을 못 찾는다.

클래스형 vs 함수형 컴포넌트 보충

책은 클래스형으로 시작하지만, 요즘은 거의 함수형을 쓴다. 위 예제를 함수형으로 쓰면 :

// 함수형 : 함수가 JSX 를 return 하면 끝 (render 메서드, Component 상속 필요 없음)
function R003_ImportConponet() {
  return <h2>[THIS IS IMPORTED COMPONENT]</h2>
}

export default R003_ImportConponet
구분클래스형함수형
모양class X extends Component { render() { return (...) } }function X() { return (...) }
상태 관리this.state, this.setStateuseState 같은 Hook
지금옛 코드·책에서 자주 보임. React 19 에서도 동작현재 표준 (Vite 기본 App.jsx 도 함수형)

4. 생명주기 함수 (예제 4 ~ 8)

클래스형 컴포넌트에는 React 가 정해진 시점에 자동으로 호출하는 메서드들이 있다. 이를 생명주기(LifeCycle) 함수라고 한다. 내가 호출하는 게 아니라 React 가 이름으로 찾아서 호출한다.

순서생명주기 함수 (마운트 : 처음 화면에 올라갈 때)하는 일
1constructor(props)생성자. state 선언, props 초기화
2static getDerivedStateFromProps(props, state)props 를 보고 state 조정
3render()화면(JSX) 만들기
4componentDidMount()화면에 붙은 직후 한 번 (예제 7)

코드에 적은 위치는 상관없다. R006 처럼 getDerivedStateFromProps 를 constructor 보다 위에 적어도 실행 순서는 React 가 정한 대로다.

4-1. render() (예제 4)

// src/R004_LifeCycleEx.jsx
import React, { Component } from 'react';

class R004_LifecycleEx extends Component {
    render() {
        console.log('3. render Call');
        return (
            <h2>[THIS IS RENDER FUNCTION]</h2>
        )
    }
}

export default R004_LifecycleEx;
  • 화면에 그릴 JSX 를 return 하는 함수. 클래스형 컴포넌트에 반드시 있어야 한다
  • 보충 처음 마운트될 때뿐 아니라 props 나 state 가 바뀔 때마다 다시 호출된다
  • 보충 render 안에서는 화면을 계산만 한다. 여기서 state 를 바꾸면(setState) 다시 render → 무한 반복이 된다

4-2. constructor(props) (예제 5)

// src/R005_LifeCycleEx.jsx
class R005_LifecycleEx extends Component {
    constructor(props) {
        super(props);                    // 가장 위에서 먼저 호출!
        this.state = {};                 // 컴포넌트 안에서 쓸 변수(state) 선언
        console.log('1. constructor Call');
    }
    render() {
        console.log('3. render Call');
        return (
            <h2>[THIS IS CONSTRUCTOR FUNCTION]</h2>
        )
    }
}
  • 생명주기 함수 중 가장 먼저 실행되고, 처음 한 번만 호출된다
  • 컴포넌트 내부에서 사용되는 변수(state)를 선언하고, 부모 객체에서 전달받은 변수(props)를 초기화할 때 사용한다
  • super(props) 는 가장 위에서 호출해야 한다

보충 super(props) 는 부모 클래스(Component)의 생성자를 부르는 것. 이게 끝나야 this 를 쓸 수 있어서, super 전에 this.state 를 쓰면 ReferenceError 가 난다 (C++ 의 부모 생성자 호출과 같은 개념). constructor 안에서는 this.setState() 대신 this.state = { ... } 로 직접 대입한다.

4-3. getDerivedStateFromProps (예제 6)

// src/R006_LifeCycleEx.jsx
class R006_LifecycleEx extends Component {
    static getDerivedStateFromProps(props, state) {
        console.log('2. getDerivedStateFromProps Call :' + props.prop_value);
        return {};                       // state 에 합칠 객체 (바꿀 게 없으면 null)
    }
    constructor(props) {
        super(props);
        this.state = {};
        console.log('1. constructor Call');
    }
    render() {
        console.log('3. render Call');
        return (
            <h2>[THIS IS CONSTRUCTOR FUNCTION]</h2>
        )
    }
}
// src/App.jsx : 부모가 prop_value 를 넘겨준다
import LifecycleEx from './R006_LifeCycleEx'
...
<LifecycleEx prop_value="FromApp.jsx" />

1. constructor Call
2. getDerivedStateFromProps Call :FromApp.jsx
3. render Call
  • getDerivedStateFromProps 는 React 가 예약해 둔 이름이다. 이걸로 props 를 받아서 state 를 조정한다
  • 호출 순서 : constructor → getDerivedStateFromProps → render
  • 컴포넌트가 새로운 props 를 받게 됐을 때 state 를 변경해 준다 (마운트 때와 다시 그릴 때마다 render 직전에 호출)
왜 이런가 보충설명
constructor 다음state 를 고치는 함수라서 constructor 에서 this.state 가 먼저 만들어져 있어야 한다
render 앞조정한 state 로 화면을 그려야 하니까
static클래스에 붙은 함수라 this 를 못 쓴다. 받은 props, state 만 보고 바꿀 내용을 객체로 return → React 가 state 에 합친다

보충 생명주기 함수는 이름을 틀리면 에러 없이 그냥 호출되지 않는다. 콘솔에 로그가 안 찍히면 철자부터 확인. 또 class X extends Componet 처럼 Component 철자가 틀리면 ReferenceError: Componet is not defined 로 화면 전체가 하얗게 된다 → F12 Console 에서 확인. getDerivedStateFromProps 는 실무에서는 거의 쓰지 않는다. 지금은 순서 이해용.

4-4. componentDidMount 와 state 합치기 (예제 7)

// src/R007_LifeCycleEx.jsx
class R007_LifecycleEx extends Component {
    static getDerivedStateFromProps(props, state) {
        console.log('2. getDerivedStateFromProps Call :' + props.prop_value);
        return { tmp_state: props.prop_value };   // ← state 에 합쳐 달라는 요청
    }
    constructor(props) {
        super(props);
        this.state = {};                           // 처음엔 빈 객체
        console.log('1. constructor Call');
    }
    componentDidMount() {
        console.log('4. componentDidMount Call');
        console.log('5. tmp_state : ' + this.state.tmp_state);
    }
    render() {
        console.log('3. render Call');
        return (
            <h2>[THIS IS CONSTRUCTOR FUNCTION]</h2>
        )
    }
}
// 콘솔
1. constructor Call
2. getDerivedStateFromProps Call :FromApp.jsx
3. render Call
4. componentDidMount Call
5. tmp_state : FromApp.jsx
  • componentDidMount : render 가 끝나 화면에 실제로 붙은 직후 한 번 호출된다
  • 보충 서버에서 데이터 가져오기, 타이머 시작처럼 화면이 준비된 뒤 할 일을 주로 여기에 넣는다

tmp_state 는 어디서 정의됐나?

constructor 에서 선언한 적이 없는데 this.state.tmp_state 가 나온다. 정의한 곳은 getDerivedStateFromProps 가 return 한 객체다.

순서함수this.state
1constructor{} (빈 객체)
2getDerivedStateFromProps{ tmp_state: 'FromApp.jsx' } 를 return → React 가 state 에 합침 → { tmp_state: 'FromApp.jsx' }
3render합쳐진 state 로 화면을 그림
4componentDidMountthis.state.tmp_state → 'FromApp.jsx'

return 했을 뿐인데 왜 state 에 합쳐지나? : React 내부 규칙

  • 보통 JavaScript 에서 return 은 호출한 쪽에 값을 돌려줄 뿐이다. 아무도 받지 않으면 버려진다
  • 그런데 getDerivedStateFromProps 는 내가 아니라 React 가 호출한다. 그러니 return 값도 React 가 받고, React 가 그 값을 this.state 에 합친다
  • 그 코드는 내 파일이 아니라 React 안(node_modules) 에 있어서 안 보일 뿐이다
// React 안에서 일어나는 일 (단순화한 흉내)
const instance = new R007_LifecycleEx(props)                  // 1. constructor → state = {}
const result = R007_LifecycleEx.getDerivedStateFromProps(props, instance.state)  // 2. React 가 호출하고 받음
if (result !== null) {
    instance.state = { ...instance.state, ...result }       //    React 가 합침
}
instance.render()                                             // 3. 화면 그리기
instance.componentDidMount()                                  // 4. 화면에 붙은 뒤
state 에 합쳐지는 것은 React 가 정한 내부 규칙(약속)이다. JavaScript 문법이 아니다.
· getDerivedStateFromProps 의 return 객체 → state 에 합친다 (null 이면 그대로)
· render 의 return JSX → 화면에 그린다
· 나중에 배울 this.setState({ ... }) 에 넘긴 객체 → state 에 합친다

보충 C 의 qsort 와 같은 구조다. 나는 비교 함수 compare 가 결과를 return 하게만 만들고, 그 값으로 배열을 정렬하는 코드는 qsort 안에 있다. 이처럼 라이브러리(프레임워크)가 내 함수를 호출하는 구조를 제어의 역전(Inversion of Control) 이라고 한다. JavaScript 노트 10-5 의 콜백 함수와 같은 원리.

합치는 규칙 : 속성 이름 기준

내용을 이해해서 합치는 게 아니라 같은 이름의 속성끼리 덮어쓰기만 한다 (JavaScript 노트 11-9 의 객체 전개 연산자 { ...a, ...b } 와 같다).

기존 state : { count: 1, tmp_state: '옛 값' }
return 값  : { tmp_state: 'FromApp.jsx' }
합친 결과  : { count: 1, tmp_state: 'FromApp.jsx' }
return 값에결과
새 이름이 있으면추가 (R007 의 tmp_state)
같은 이름이 있으면덮어씀
없는 이름은기존 값 유지
null 을 return아무것도 안 바꿈

JavaScript 객체는 동적이라 미리 선언하지 않은 속성도 언제든 생긴다 (C 구조체와 다른 점). constructor 에서 this.state = { tmp_state: '' } 처럼 미리 적어 두면 읽기 좋지만 필수는 아니다. 대신 없는 속성을 읽어도 에러 없이 undefined 가 나오므로, 콘솔에 tmp_state : undefined 가 찍히면 철자부터 확인한다.

4-5. setState 와 shouldComponentUpdate (예제 8)

// src/R008_LifeCycleEx.jsx
class R008_LifecycleEx extends Component {
    static getDerivedStateFromProps(props, state) {
        console.log('2. getDerivedStateFromProps Call :' + props.prop_value);
        return { tmp_state: props.prop_value };
    }
    constructor(props) {
        super(props);
        this.state = {};
        console.log('1. constructor Call');
    }
    componentDidMount() {
        console.log('4. componentDidMount Call');
        console.log('5. tmp_state : ' + this.state.tmp_state);
        this.setState({ tmp_state2: true });       // ← state 변경 → 업데이트 단계 시작
    }
    shouldComponentUpdate(props, state) {
        console.log('6. shouldComponentUpdate Call / tmp_state = ' + state.tmp_state2);
        return state.tmp_state2;                   // true 면 다시 render
    }
    render() {
        console.log('3. render Call');
        return (
            <h2>[THIS IS shouldComponentUpdate FUNCTION]</h2>
        )
    }
}
// 콘솔
1. constructor Call                                  ┐
2. getDerivedStateFromProps Call :FromApp.jsx        │ 마운트
3. render Call                                       │
4. componentDidMount Call                            │
5. tmp_state : FromApp.jsx                           ┘ ← 여기서 setState
2. getDerivedStateFromProps Call :FromApp.jsx        ┐
6. shouldComponentUpdate Call / tmp_state = true     │ 업데이트
3. render Call                                       ┘ ← 한 번 더 render
  • setState() 함수는 변수의 선언과 초기화를 동시에 할 수 있다. tmp_state2 는 state 에 없던 이름인데 setState({ tmp_state2: true }) 한 번으로 생기면서 값이 들어간다 (기존 state 에 합쳐진다)
  • state 의 변경이 발생했기 때문에 변경(업데이트) 단계의 생명주기 함수 shouldComponentUpdate() 가 실행된다
  • shouldComponentUpdate 는 Boolean 을 반환하는데, return 값이 true 일 경우 render() 를 한 번 더 호출한다. false 면 다시 그리지 않는다
포인트 보충설명
업데이트 때도 getDerivedStateFromProps콘솔에 2번이 한 번 더 찍힌다. 이 함수는 마운트뿐 아니라 render 직전마다 호출되기 때문
shouldComponentUpdate 의 매개변수바뀔 예정인 새 값(nextProps, nextState) 이 들어온다. 그래서 state.tmp_state2 가 true. 현재 값은 this.state
false 를 반환하면render 를 건너뛴다 (state 값은 바뀐다). 다시 그릴 필요가 없을 때 성능 최적화용으로 쓴다
constructor 와의 차이constructor 에서는 this.state = { } 직접 대입. 그 뒤로는 반드시 setState (직접 바꾸면 React 가 몰라서 화면이 안 바뀜)

보충 this.state 는 React 가 지켜보는 특별한 이름이다. setState 로 바꾸면 React 가 알아채고 업데이트 단계(→ render)를 돌린다. this.state.x = 1 처럼 직접 바꾸면 값만 바뀌고 화면은 그대로다. componentDidMount 에서 setState 를 하면 render 가 한 번 더 일어나므로, 꼭 필요할 때만 쓴다.

4-6. props : 부모가 넘겨주는 값

  • props = properties(속성) 의 준말. HTML 태그에 속성을 붙이듯 컴포넌트 태그에 붙인 속성들을 모은 객체
  • <LifecycleEx prop_value="FromApp.jsx" /> → 자식은 props = { prop_value: "FromApp.jsx" } 를 받는다
  • prop_value 는 예약어가 아니라 책에서 정한 이름. 양쪽 이름만 맞추면 아무 이름이나 된다
  • 클래스형 컴포넌트의 메서드 안에서는 this.props.prop_value 로 꺼낸다 보충
  • 문자열은 "...", 숫자나 JS 값은 { } 로 넘긴다 : <X age={30} /> 보충
구분예
React 가 정한 이름props(매개변수 이름은 관례), render, constructor, getDerivedStateFromProps, componentDidMount, state, setState
내가 정하는 이름prop_value 같은 속성 이름, 컴포넌트 이름
피해야 할 속성 이름 보충key, ref (React 가 따로 씀, props 로 안 넘어감), children (태그 사이 내용)

4-7. 콘솔에 두 번씩 찍히는 이유 : StrictMode 보충

  • main.jsx 의 <StrictMode> 는 개발할 때만 동작하는 검사 모드. constructor, getDerivedStateFromProps, render 를 일부러 두 번씩 호출한다
  • 같은 입력이면 같은 결과가 나와야 하는 함수에 숨은 버그(부수 효과)를 찾기 위해서. 배포용(npm run build)에서는 한 번만 실행된다
  • 책처럼 한 번씩 보고 싶으면 잠시 main.jsx 를 createRoot(...).render(<App />) 로 바꾼다 (공부 후 다시 켜기)

복습 퀴즈 (눌러서 답 확인)

1. 개발 서버를 켜는 명령과 접속 주소는?

react_study 폴더에서 npm run dev, 주소는 http://localhost:5173/. 터미널을 닫으면 서버도 꺼진다.

2. 책의 App.js 와 index.js 는 내 프로젝트에서 어떤 파일인가?

App.js → src/App.jsx, index.js → src/main.jsx. 새 파일은 확장자를 .jsx 로 만든다.

3. JSX 에서 class 대신 쓰는 속성은? JS 값을 넣는 방법은?

className. JS 값은 { } 안에 넣는다.

4. return 할 때 ( ) 대신 { } 를 쓰면?

JavaScript 가 객체를 돌려주는 것으로 읽어서 문법 에러가 난다. JSX 는 소괄호로 감싼다.

5. 컴포넌트를 다른 파일에서 쓰려면?

컴포넌트 파일에서 export default 로 내보내고, 쓰는 파일에서 import 이름 from './파일' 한 뒤 <이름 /> 태그로 쓴다. 이름은 대문자로 시작.

6. <X></X> 와 <X /> 의 차이는?

내용이 없을 때는 결과가 같다. 사이에 내용(children)을 넣을 때만 여는/닫는 태그를 쓴다.

7. 마운트 때 생명주기 함수의 호출 순서는?

constructor → getDerivedStateFromProps → render (→ componentDidMount). 코드에 적은 순서와 상관없다.

8. constructor 에서 하는 일과 super(props) 를 맨 위에 쓰는 이유는?

state 선언과 props 초기화. 처음 한 번만 호출된다. super 로 부모(Component) 생성자를 먼저 불러야 this 를 쓸 수 있다.

9. getDerivedStateFromProps 는 왜 static 이고 무엇을 return 하나?

this 를 쓰지 못하게 해서 받은 props·state 만으로 계산하게 하려고. state 에 합칠 객체를 return 하고, 바꿀 게 없으면 null.

10. props 는 무엇의 준말이고 prop_value 는 예약어인가?

properties(속성). 부모가 컴포넌트 태그에 붙인 속성들의 객체다. prop_value 는 책이 정한 이름일 뿐 예약어가 아니다.

11. 콘솔에 로그가 두 번씩 찍히는 이유는?

main.jsx 의 StrictMode 가 개발 중에 버그를 찾으려고 일부러 두 번 호출하기 때문. 배포용에서는 한 번.

12. componentDidMount 는 언제 호출되고 주로 무엇을 넣나?

render 가 끝나 화면에 실제로 붙은 직후 한 번. 서버 데이터 가져오기, 타이머 시작처럼 화면이 준비된 뒤 할 일.

13. R007 에서 constructor 에 없던 tmp_state 가 생긴 이유는?

getDerivedStateFromProps 가 { tmp_state: ... } 를 return 했고, React 가 그 객체를 state 에 합쳤기 때문. JS 객체는 동적이라 미리 선언하지 않아도 속성이 생긴다.

14. return 만 했는데 state 에 합쳐지는 이유는?

그 함수를 호출하는 쪽이 React 이고, return 값을 state 에 합치는 것이 React 의 내부 규칙이기 때문 (제어의 역전, qsort 의 compare 와 같은 구조). 같은 이름은 덮어쓰고 새 이름은 추가, 없는 이름은 유지.

15. 업데이트 단계의 생명주기 함수 순서는?

getDerivedStateFromProps → shouldComponentUpdate → render → getSnapshotBeforeUpdate → componentDidUpdate. 언마운트 때는 componentWillUnmount.

16. R008 에서 setState 를 호출하면 무슨 일이 일어나나?

state 에 tmp_state2 가 선언과 동시에 true 로 합쳐지고, state 가 바뀌었으므로 업데이트 단계가 시작된다 : getDerivedStateFromProps → shouldComponentUpdate → (true 이므로) render 한 번 더.

17. shouldComponentUpdate 가 false 를 반환하면?

render 를 다시 호출하지 않는다 (화면 갱신 생략). 불필요한 다시 그리기를 막는 성능 최적화에 쓴다.

18. state 를 this.state.x = 1 로 직접 바꾸면?

값은 바뀌지만 React 가 알아채지 못해 화면이 갱신되지 않는다. constructor 이후에는 반드시 setState 를 쓴다.
